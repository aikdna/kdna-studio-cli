# Creation command contract

Status: machine contract for the Creation Engine commands shipped in the
published `0.11.0` Studio CLI. It is for Host adapter implementers, not an
ordinary-user questionnaire and not a promise that every Host exposes the
full surface.

## Command set

```text
guide-agent
create-agent
inventory-agent
deliver-material
resume
status
answer
review
try
repair
export-agent
finalize-agent
```

Each command accepts `--json`. Private structured input uses `--input-file` or
`--input-stdin`. Natural-language source or judgment content, passwords, and
API keys are rejected from argv. The Host generates and privately persists
machine fields such as `mode`, `workflow_mode`, `created_by`, `operation_id`,
revision, and digest; it must not ask the user to fill them in.

`guide-agent --action create` returns the current public create template.
`guide-agent <workspace>` returns the exact next action and supported machine
template. A Host must not inspect installed package source or private workspace
JSON to reconstruct an undocumented action. If the guide reports an
action-specific template or official adapter gap, that gap is a product
blocker rather than permission to hand-compose internal receipts.

## Result envelope

Success returns one JSON document on stdout. Diagnostics go to stderr. The
envelope includes:

```json
{
  "document_type": "kdna.creation-command-result",
  "workspace": {
    "state": "in_progress",
    "semantic_revision": 1
  },
  "readiness": {
    "compile_ready": false,
    "judgment_accepted": false,
    "completion_gates": {
      "format_valid": false,
      "judgment_accepted": false,
      "application_verified": false,
      "creation_complete": false
    }
  },
  "next_action": {
    "action": "review_candidates",
    "required_actor": "creating-agent",
    "requires_user": false,
    "unresolved_ids": []
  }
}
```

`compile_ready` is not `FORMAT_VALID`; it says only that the current judgment
model may be compiled into a managed test candidate. `judgment_accepted` is the
second gate, not Creation Complete. New schema output does not expose
ambiguous legacy aliases.

Normal command output may contain private state and therefore is not a public
log payload. It never contains raw material bodies, source absolute paths,
passwords, decrypted Runtime payloads, role private keys, or provider response
bodies.

## Explicit execution and authority

`workflow_mode` is `collaborative` or `autonomous`. Authority `mode` is one of:

```text
agent-authored
human-confirmed
organization-confirmed
interpretive
mixed-authorship
```

Human participation is a private receipt, not a sixth mode. Both fields are
explicit for new workspaces; the CLI does not silently infer collaborative
execution or authorship. The Host may derive a conservative proposal from the
user's ordinary words, then asks only when representation or authorship is
ambiguous.

## Idempotency and recovery

Every mutation has a caller-stable operation coordinate generated by the Host.
An exact retry at the same semantic coordinate is inert. Reusing an operation
ID with different input, bytes, destination, or state fails closed.

Private saves are atomic. `resume` reports the next required actor/action and
restores an interrupted managed-candidate or final-delivery transaction. A
fresh Host does not need previous chat context. An outdated private workspace
returns a specific schema migration requirement rather than guessing a new
authority.

## Material inventory

`inventory-agent` accepts explicit files or directories. Before approval it
does not read content and returns a public projection with:

- relative display path and source kind;
- `eligible`/`awaiting-approval`, excluded, unsupported, duplicate, uncertain,
  or failed status;
- extractor/Host-observation capability;
- operation batch continuation;
- inventory and processing-policy digests.

The processing policy explicitly binds local-only execution, a named remote
processor and boundary, or prohibited processing, plus
`host-declared` or `verified-host-required` assurance. A caller-supplied
capability digest is only a coordinate and never proves locality. The generic
CLI refuses `verified-host-required` delivery unless a separately trusted Host
adapter is available. Missing policy,
destination drift, file drift, workspace overlap, or a symlink escape fails
closed. An input directory may contain the private workspace; the exact
workspace subtree is excluded. The workspace itself or a material root inside
it is rejected.

`deliver-material` releases only an approved entry through one Host-owned
channel. A standard named-remote terminal Host uses
`--private-output-file <precreated-mode-0600-system-temp-file>` and deletes the
file in `finally`; a dedicated adapter may use `--private-output-fd 3`. The two
options are mutually exclusive. A regular file/fd must be Host-owned, deny
group/other access, avoid symlinks, and not alias stdout/stderr. The command
verifies file identity and exact bytes again and clears transient buffers. Raw
content is never returned in command JSON. The Host may place those bytes into
the approved named model context under its declared retention boundary. This
is Host-declared remote processing, not verified-local evidence or a claim
that model input is log-free.

Direct text is strict UTF-8 and untruncated. PDF/word-processing extraction is
capability-probed. A Host-observed image/audio/video/binary uses an exact
streamed source digest plus bounded observation text and a digest-bound
observer/tool/coverage record. Large source media is not buffered merely to
hash it.

Exact byte duplicates are deduplicated across operations and batches. Existing
unchanged materials do not consume the next continuation budget. Any new,
changed, deleted, or reclassified entry requires a new content-free review.
Directory continuation does not imply offset continuation inside one file.
One text file above the direct-processing byte limit is
`single-file-chunking-not-implemented`; the caller may provide an explicitly
selected, ordered, full-coverage split copy or exclude it.

## Mutation commands

- `answer` requires explicit actor, subject, expected revision, and current
  pre-answer semantic coordinate. Question-kind disposition decides whether
  the issue is actually resolved; arbitrary prose does not close a conflict,
  source-safety, test, or application failure.
- `review` records source review (including `reviewed-no-change`), candidate
  promotion/rejection, relation decisions, confirmation, import mapping, and
  bounded uncertainty disposition.
- `try` freezes and records semantic or application evidence in separate
  ordered requests.
- `repair` turns current failures into bounded repair items. A semantic repair
  invalidates confirmations, tests, managed candidates, and application
  evidence.

## Coverage and stability

Semantic and application plans derive required dimensions from declared
structure and risk. A simple one-unit asset may use one applicable task and one
boundary/exit task. Existing high-risk or unique units, global critical
boundaries, conflicts, priority, exception, or authority-precedence must be
covered; absent structures are not invented.

The application contract is `application-adoption-fidelity`. Each task is
`with-only` or `paired-diagnostic`. Only the latter has an isolated baseline
lane. No observed difference is not a failure and is not causal proof.

At least one pre-frozen core or highest-risk boundary scenario supplies the
repeated evidence required for stable use. Each repetition binds actual
Consumer output and per-task independent evaluation, and the Engine
mechanically recomputes stability. Caller-provided `stable: true`, unrelated
digests, missing rounds, changed order, or altered outputs cannot pass.

## Managed candidate

`export-agent` creates and verifies an exact managed test candidate inside the
private workspace:

```bash
kdna-studio export-agent <workspace> --json
```

It takes no user `--out` path. The build receipt can establish `FORMAT_VALID`
for exact bytes, including a technically valid encrypted container when the
current caller lacks authorization. Actual authorized Runtime load and
projection belong to `APPLICATION_VERIFIED`.

The official Host, not the ordinary user, owns fresh Consumer/evaluator
isolation, task delivery, signing, and receipt submission. The creating Agent
cannot self-evaluate. A Host without a conforming orchestration adapter must
report that blocker.

## Final delivery

`finalize-agent` is available only when all three gates bind the same semantic
and asset digests:

```bash
kdna-studio finalize-agent <workspace> --out <file.kdna> --json
```

It verifies managed bytes against build/application/completion receipts and
atomically copies those exact bytes without recompiling. It rejects a target
inside the workspace, path aliases, symlink escapes, stale receipts, changed
bytes, and partial transactions before leaving a target. Copying already
verified encrypted bytes does not request a redundant password.

Runtime `access: public` is an authorization mode: anyone possessing the file
can load it without an additional KDNA secret. It is not an Internet
publication action. Distribution and publication are separate caller actions
and are never inferred by Creation.

## Secret transport

All secret-bearing stdin readers use a bounded, strict UTF-8 transport
decoder. It removes at most one terminal LF or CRLF, preserves all other
leading/trailing whitespace, rejects empty/oversize/invalid UTF-8 input, and
clears transient buffers. Studio and Runtime must interpret the same
authorized secret bytes.
